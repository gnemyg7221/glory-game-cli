# 用 glory-game CLI 接入新游戏（以水果配为例）

本文记录把 OPPO 主库广告 SDK 接到 **ShuiGuoPeiPeiDui（水果配，`fruits-clear`）** 时的完整步骤，以及这次实际踩过的坑。下一款 3.8.x 竖屏游戏按同样顺序走。

游戏仓库示例路径：

```
/Users/aemon/Documents/project_new_games/ShuiGuoPeiPeiDui
```

包名：`com.evolution.shuiguopei.app.nearme.gamecenter`  
引擎：Cocos Creator **3.8.6**  
方向：竖屏

日常只用这三条，不要默认跑 `integrate`（会编 Gradle）：

```text
init-config  →  apply  →  cocos-build
```

Android Studio 打开的永远是最新生成目录：

```text
build/android-<时间戳>/proj
```

不要打开 `native/engine/android`。那是进 git 的模板，不是这次要 Run 的工程。

---

## 0. 对方电脑必须先齐的工具链

路径可以和你不一样，**版本必须和 `glory-game.yaml` 一致**。CLI 现在会在 `cocos-build` 前检查，缺了直接停。

| 项 | 水果配 / 共用配置 |
|---|---|
| Node.js | 18+ |
| Cocos Creator | 3.8.6（`/Applications/Cocos/Creator/3.8.6/`） |
| JDK | **11**（不要用 Android Studio 自带 17 去跑 Gradle） |
| Android SDK | `ANDROID_SDK_ROOT` 或 `~/Library/Android/sdk` |
| compileSdk / platform | `android-29` |
| Build Tools | `30.0.3` |
| NDK | **`21.4.7075529`**（不要用 SDK Manager 里最新的 29.x） |
| CMake | `3.22.1` |
| AGP / Gradle Wrapper | `7.4.2` / `7.6.3`（CLI 生成工程时会钉死） |

macOS 找 JDK 11：

```bash
/usr/libexec/java_home -v 11
```

NDK 装到：

```text
$ANDROID_SDK_ROOT/ndk/21.4.7075529
```

广告位、`app_key`、游戏中心密钥这次可以先空着。Debug 能进游戏即可。激励日志里 `posId` 为 `null` 是预期，不是崩因。

## 1. 安装 CLI

CLI 是独立仓，不在游戏仓里。本机注册一次：

```bash
cd /Users/aemon/Documents/project_new_games/glory-game-cli
npm link
glory-game version
```

应看到 `0.5.0` 或更高。之后任意目录都能跑 `glory-game`。

---

## 2. 指定游戏工程

```bash
glory-game use --project /Users/aemon/Documents/project_new_games/ShuiGuoPeiPeiDui
```

以后省略 `--project` 也会记住这个目录。换游戏再 `use` 一次。

先看本机缺什么：

```bash
glory-game inspect
```

Creator、JDK 11、NDK 21.4、CMake、platform、build-tools 必须是 pass。fail 先装，不要往下走。

---

## 3. 生成 `glory-game.yaml`

```bash
glory-game init-config
```

终端**只问包名**。水果配填：

```text
com.evolution.shuiguopei.app.nearme.gamecenter
```

游戏名、Creator 版本从 `package.json` 读。JDK / AGP / Gradle / NDK / CMake / SDK 子模块地址和 commit 用内置的 `glory-oppo-cocos-3.8-v1`。

生成后立刻打开 `glory-game.yaml`，确认至少有：

```yaml
cocos:
  version: 3.8.6
  startScene: assets/scene/Main.scene
android:
  javaVersion: 11
  ndkVersion: 21.4.7075529
sdk:
  commit: ccaef3e1ef6821928c850bd1858acafa7ab975f5
```

`startScene` 必须写进 yaml 并提交。对方电脑没有你的 `profiles/`（已被 gitignore），不写就会落到 Creator 的第一个场景。

水果配这次若没写，会进空的 `assets/scene.scene`（只有 Canvas 和黑相机），浏览器预览却是好的，因为预览走 `Main`。

识别顺序：yaml → Cocos 构建配置 → 工程里只有一个场景 → 有脚本的场景 vs 空场景 → 认不出来才问。认出来的路径不对就手改 yaml。

广告、隐私、密钥不要写进 yaml，以后改宿主文件。

---

## 4. 接入宿主（apply）

```bash
glory-game apply
```

不要用 `glory-game integrate`。`integrate` 会接着跑 Gradle 编 APK，日常不需要。

`apply` 会：

- 调整 `.gitignore`，让 `native/engine/android` 能进 git
- 改 Manifest、`app/build.gradle`、`AppActivity`、`MyApplication`、`supplierconfig.json`、`cocos-settings.gradle`
- 把 `glory-adsdk` 加成子模块，并 checkout 到 yaml 里钉死的 commit
- 打开 AndroidX + Jetifier
- 备份改过的文件到 `build/glory-cli/backups/<时间戳>`

广告参数没填时，宿主先留空，这是正常的。

检查子模块指针：

```bash
git -C native/engine/android/glory-adsdk rev-parse HEAD
```

必须是 yaml 里的 `ccaef3e1...`。不要把 SDK 仓里的本地脏改动（例如跳过开屏广告）提交进 SDK 共用仓。

---

## 5. 游戏侧两件必须看的事

### 5.1 多纹理插件

水果配有 `assets/resources/multTextures/MultTextures.ts`。真机上必须：

```ts
const SUPPORT_NATIVE = false;
```

`false` 表示 **Android 原生不要走多纹理合批**。开着会黑屏或渲染异常。浏览器预览看不出来。

### 5.2 启动场景

工程里可能有两个场景：

| 路径 | 实际内容 |
|---|---|
| `assets/scene.scene` | 空场景，黑相机 |
| `assets/scene/Main.scene` | 真正入口，有 UIScene |

yaml 必须指向 `Main.scene`。CLI 不传 `startScene` 时，Creator 用资源列表第一个场景。

---

## 6. 生成 Android 工程

```bash
glory-game cocos-build
```

默认 `--mode debug`。会：

1. 按 yaml 检查 JDK / SDK / NDK / CMake，不对就停
2. 把 `sdkPath`、`ndkPath`、`javaHome` 传给 Creator，避免 Creator 自己选最新 NDK
3. 输出到 `build/android-<UTC时间戳>/`
4. 改生成工程：AGP 7.4.2、Gradle 7.6.3、`PROP_NDK_PATH` 钉到 21.4、`org.gradle.java.home` 钉到这台机器的 JDK 11

控制台会打印启动场景来源。必须是 `glory-game.yaml`。如果提示「未写入 yaml」，停下来把路径提交进配置，再编一次。

输出目录已存在会拒绝覆盖，换一个 `--output-name` 或删掉旧目录。

## 7. 用 Android Studio 安装

打开**最新**的：

```text
ShuiGuoPeiPeiDui/build/android-20260910TxxxxxxZ/proj
```

不要打开 `native/engine/android`。

用 Studio 的 Run 装到真机。日常不要跑 `glory-game android-build` / Gradle 来「验证功能」。

装完看 logcat：

```text
Success to load scene: db://assets/scene/Main.scene
```

如果是 `db://assets/scene.scene`，就是启动场景又错了。

## 8. 真机上这次踩过的运行问题

### 8.1 进游戏黑屏

日志已经 `Success to load scene`，但加载的是空场景。原因见 5.2。改 yaml 的 `startScene` 后必须重新 `cocos-build` 再装。

### 8.2 玩一两分钟后闪退（SIGABRT）

Debug 引擎断言：

```text
RenderEntity::setStaticDrawInfoSize
size <= STATIC_DRAW_INFO_CAPACITY   （容量是 4）
```

Creator 3.8.6 **原生 Debug** 里，STATIC 类型的 2D 渲染实体最多 4 份 drawInfo。局内 Label / 对象池 / 粒子反复申请会超。浏览器没有这条原生断言，所以编辑器里是好的。

水果配的处理：`assets/script/fix/NativeStaticDrawInfoGuard.ts`，从 `UIScene` 启动时挂上。超 4 份时复用最后一槽，进程不再被杀掉。Release 包会编掉这条 assert，但超限仍可能画错，所以 Debug 也要挡。

篮子飘字不要同时开描边和 `Label.CacheMode.CHAR`，改成 `BITMAP`。

### 8.3 通关后小车开过去，画面没了

点「下一关」会用 `MUTEX` 打开 `UITransition`，此时上一关 `UIGame` 已经被拆掉，屏幕上只剩过场。小车动画最后一帧就是开出画面。

如果把车的 Spine 改成 `PRIVATE_CACHE`，`setTrackCompleteListener` 经常不回调，`gameStart()` 不会跑，就会停在空白过场。

正确做法：过关车保持 **REALTIME**。回调丢了也要有超时强制进下一关。不要用缓存模式去「治」8.2 的闪退，那是两回事。

改了脚本或 prefab 必须重新 `cocos-build` 再装。旧 APK 里没有新防护。

### 8.4 开屏广告、激励视频

本地调试可以把 `GloryAdLaunchActivity` 改成登录后直接 `jumpToAppActivity()`，**不要提交 SDK 子模块**。激励 `adId不存在` / `posId null` 是后台没配，不是崩溃原因。

## 9. 什么进 git，什么不要

游戏仓要提交：

- `glory-game.yaml`（含 `startScene`）
- `.gitignore` 对 `native/engine/android` 的放开
- `apply` 改过的宿主文件
- `glory-adsdk` **子模块指针**（仍指向共用 commit）
- 游戏侧修复（多纹理开关、启动场景、drawInfo 防护、过关车回调）

不要提交：

- `profiles/`、`library/`、`temp/`、`build/`（本机 Creator 状态）
- `settings/v2/packages/information.json` 这类表单 sid
- SDK 仓里跳过开屏广告的脏改动
- 密钥、签名密码

`build/` 里的 `org.gradle.java.home` 是**这台机器**的 JDK 路径，每人自己跑一遍 `cocos-build` 就会写成自己的。

---

## 10. 给下一款游戏的最短清单

1. 对方先装 JDK 11、NDK `21.4.7075529`、CMake `3.22.1`、Creator 版本与 `package.json` 一致。
2. `npm link` CLI，`glory-game use --project <新游戏>`。
3. `inspect` 全绿。
4. `init-config` 只填包名，确认 yaml 里的 `startScene` 是真正入口，不是空场景。
5. `apply`，不要 `integrate`。
6. 有多纹理插件就关原生：`SUPPORT_NATIVE = false`。
7. `cocos-build`。
8. Android Studio 打开最新 `build/android-*/proj`，Run 真机。
9. logcat 确认加载的是入口场景。
10. 改游戏代码后必须再 `cocos-build` 再装，改 prefab 只留在编辑器里不算。

CLI 不会替对方装 JDK/NDK。Android Studio 里若手工把 Gradle JDK 改成 17，仍可能绕过 `org.gradle.java.home`。
